# Как устроен Telegram-бот

## 1. Два вида кнопок

В боте используются два разных типа Telegram-клавиатур.

### Постоянная кнопка под полем ввода пользователя

После `/start` бот отправляет `ReplyKeyboardMarkup` с кнопкой:

```text
☰ Меню
```

Это не кнопка на сообщении бота. Она находится в нижней панели пользователя, рядом со строкой ввода. При нажатии Telegram отправляет боту обычный текст `☰ Меню`, а обработчик `bottom_menu_handler` снова показывает главное меню.

Кнопка сделана постоянной через:

```python
ReplyKeyboardMarkup(
    [[KeyboardButton("☰ Меню")]],
    resize_keyboard=True,
    is_persistent=True,
)
```

### Кнопки внутри сообщений бота

Выбор ориентации, длительности и качества сделан через `InlineKeyboardMarkup`. Эти кнопки прикреплены к сообщению бота и используются для пошагового выбора.

Одно Telegram-сообщение не может одновременно содержать ReplyKeyboardMarkup и InlineKeyboardMarkup. Поэтому `/start` отправляет два сообщения:

1. служебное сообщение, которое включает нижнюю кнопку `☰ Меню`;
2. сообщение с главным inline-меню.

## 2. Основной сценарий пользователя

```text
/start
  ↓
нижняя кнопка ☰ Меню + главное меню
  ↓
выбор режима: 🎬 Видео или 🖼 Фото
  ↓
старое меню удаляется
  ↓
выбор ориентации: 16:9 или 9:16
  ├── Видео → длительность → качество → промпт → Veo → MP4
  └── Фото  → промпт или фото с подписью → Gemini Image → PNG
```

В главном меню кнопки **🎬 Видео** и **🖼 Фото** переводят пользователя в разные режимы. Ориентация выбирается после режима и используется и для видео, и для фото.

### Ориентация

- Горизонтально — `16:9`.
- Вертикально — `9:16`.

После нажатия кнопки функция `menu_callback` сохраняет формат в `context.user_data`, удаляет старое сообщение через `query.message.delete()` и отправляет новое меню длительности.

### Длительность

Доступны кнопки:

- 4 секунды;
- 6 секунд;
- 8 секунд;
- 15 секунд.

Первые три значения напрямую передаются в `duration_seconds` API Veo.

15 секунд — это специальный режим, потому что Veo 3.1 не создаёт 15 секунд одним запросом:

1. первая часть генерируется на 8 секунд и сохраняется, но пользователю пока не отправляется;
2. результат первой операции передаётся в Veo Extension;
3. Veo добавляет продолжение примерно на 7 секунд;
4. бот полностью дожидается готовности второй операции;
5. после этого бот пытается через ffmpeg вырезать последние 7 секунд из объединённого файла;
6. если ffmpeg есть, отправляются два отдельных файла: `part1.mp4` и `part2.mp4`;
7. если ffmpeg нет, `part1.mp4` удаляется, а пользователю отправляется только `full.mp4` примерно на 15 секунд.

API Veo возвращает extension как единый файл, поэтому без ffmpeg бот не отправляет первую часть отдельно и не создаёт лишнее второе сообщение.

## 3. Выбор качества

По API Veo 3.1 доступны:

- `720p`;
- `1080p` — только для 8 секунд;
- `4k` — только для 8 секунд.

`320p` и `480p` не поддерживаются нативно. Они отображаются в меню как недоступные кнопки. В дальнейшем их можно сделать через дополнительное сжатие ffmpeg после генерации.

Для режима 15 секунд бот автоматически оставляет только `720p`, потому что видео extension ограничено этим разрешением.

## 4. Что происходит после промпта

Текст обрабатывает `text_prompt`:

1. проверяется длина и пустой текст;
2. если до этого было отправлено фото без подписи, оно используется как первый кадр;
3. берутся настройки пользователя;
4. создаётся фоновая asyncio-задача;
5. пользователь сразу получает статусное сообщение.

Для обычного видео создаётся источник:

```python
source = types.GenerateVideosSource(
    prompt=prompt,
    image=image,
)
```

Затем вызывается:

```python
operation = client.models.generate_videos(
    model="veo-3.1-generate-preview",
    source=source,
    config=types.GenerateVideosConfig(...),
)
```

## 5. Генерация фото и использование лица

Кнопка **🖼 Создать фото** устанавливает в `context.user_data` режим `generation_mode = "image"`.

### Только текст

Пользователь отправляет промпт, например:

```text
Кинематографичный портрет в неоновом городе, дождь, формат 9:16.
```

Бот вызывает модель `gemini-3.1-flash-image-preview` через `generate_content` с `response_modalities=["IMAGE"]`, получает PNG и отправляет его как фото.

### Фото с лицом и промптом

Пользователь отправляет фото с подписью:

```text
Добавь моё лицо на кинематографичный портрет в неоновом городе.
```

Или отправляет фото без подписи, а следующим сообщением пишет промпт.

Бот:

1. скачивает фотографию из Telegram в память;
2. создаёт `types.Part.from_bytes(...)` для Gemini image model;
3. добавляет инструкцию использовать лицо человека как visual identity reference;
4. передаёт фото и текст в image model;
5. сохраняет и отправляет PNG.

В режиме видео фотография передаётся Veo как `image` — стартовое изображение для анимации. Бот также добавляет в prompt инструкцию сохранить черты лица, причёску и внешность. Это помогает сохранить лицо, но модель не даёт абсолютной гарантии одинаковой идентичности в каждом кадре.

## 6. Почему генерация не блокирует бота

Генерация Veo — длительная операция. API сначала возвращает объект `operation`, а не готовый MP4.

Бот:

1. запускает генерацию в `asyncio.to_thread()`;
2. ждёт `POLL_SECONDS`;
3. обновляет операцию через `client.operations.get(operation)`;
4. повторяет проверку до `operation.done == True`;
5. скачивает файл через `client.files.download()`;
6. отправляет файл в Telegram.

Благодаря этому бот продолжает принимать команды и сообщения других пользователей.

Одновременно работают максимум `MAX_CONCURRENT_GENERATIONS` задач. Для одного пользователя одновременно разрешена только одна генерация. В `application.bot_data["active_modes"]` сохраняется активный режим пользователя:

- если занято видео, новая попытка запуска фото получает сообщение: `⚠️ Сейчас идёт генерация видео. Попробуйте запустить фото позже...`;
- если занято фото, новая попытка запуска видео получает сообщение: `⚠️ Сейчас идёт генерация фото. Попробуйте запустить видео позже...`.

Такой резерв ставится до первого `await`, поэтому два быстрых сообщения не запускают две задачи одного пользователя.

## 7. Статус и приблизительный countdown

Veo не сообщает точный процент выполнения или точное оставшееся время. Поэтому бот показывает оценочный countdown, начиная с значения из `.env`:

```dotenv
VEO_ESTIMATE_SECONDS=120
```

При значении 120 сообщение меняется примерно так:

```text
⏳ Генерирую видео
Примерно осталось: 2 мин 00 сек.
```

```text
⏳ Генерирую видео
Примерно осталось: 1 мин 30 сек.
```

```text
⏳ Генерирую видео
Примерно осталось: 59 сек.
```

Если операция длится дольше оценки, бот продолжает ждать и сообщает об этом вместо того, чтобы ошибочно считать генерацию завершённой.

## 8. Обработка лимитов

Бот распознаёт типичные ошибки Google:

- `429`;
- `RESOURCE_EXHAUSTED`;
- `quota exceeded`;
- `rate limit`;
- `too many requests`.

Если в тексте ответа Google есть `retry in 60 seconds`, `retry-after` или `retryDelay`, бот извлекает это время и показывает:

```text
⚠️ Лимит на генерацию достигнут.

Повторить можно примерно через 1 мин 00 сек
(ориентировочно в 12:00).
```

Для дневной квоты Google может не передать дату сброса. В таком случае бот сообщает, что точное время не получено, и не придумывает его.

## 9. Временные файлы

Каждая генерация работает во временной папке:

```text
veo-telegram-*/
  veo_part_1.mp4
  veo_15_seconds_combined.mp4
  veo_part_2.mp4
```

После отправки сообщения папка удаляется автоматически. Постоянное хранилище пока не используется.

## 10. Настройки пользователя

Настройки хранятся в `context.user_data` текущего процесса:

```python
{
    "aspect_ratio": "9:16",
    "duration_seconds": 8,
    "resolution": "720p",
    "long_video": False,
}
```

После перезапуска процесса настройки сбрасываются. Для постоянного хранения нужны база данных или Redis.

## 11. Безопасность

- токены находятся в `.env`;
- `.env` добавлен в `.gitignore`;
- ключи не выводятся в сообщения пользователю;
- технические ошибки сокращаются перед отправкой;
- сгенерированный файл скачивается сразу после завершения операции.

## 12. Отмена генерации

Кнопка `⏹ Отмена` находится в постоянной клавиатуре пользователя под полем ввода. Она вызывает тот же обработчик, что и `/cancel`.

Обработчик отменяет локальную asyncio-задачу бота. Уже отправленный запрос может продолжить выполняться на стороне Google, потому что отмена HTTP-запроса не гарантирует отмену удалённой операции Veo. Бот перестаёт ждать результат и освобождает пользователя для следующей задачи.

## 13. История результатов

После успешной отправки медиа функция `save_history_result` сохраняет результат в `history.db`. SQLite-таблица `generations` содержит Telegram user ID, тип результата, prompt, MIME-тип, имя файла, бинарное содержимое и время.

Кнопка `📚 История` вызывает `history_callback`. Сначала выбираются только строки текущего пользователя, затем выбранный BLOB повторно отправляется как фото или видео. Пользователь не может получить запись другого пользователя, потому что запрос к SQLite использует одновременно `id` и `user_id`.

## 14. Несколько reference-фото

Фотографии без подписи накапливаются во временном `context.user_data["pending_reference_images"]`. Максимум — три.

- одна фотография передаётся как основной `image` и может быть первым кадром видео;
- две или три фотографии преобразуются в `VideoGenerationReferenceImage` и передаются в `reference_images` Veo;
- для фото все изображения передаются как отдельные `Part.from_bytes` в Gemini Image;
- текстовый prompt запускает генерацию и очищает временный список reference-фото.

## 15. Разделяется ли prompt

Обычный prompt не делится и отправляется в модель одним запросом.

В режиме 15 секунд текст пользователя используется для первой части. Затем бот создаёт отдельный автоматический prompt продолжения для Veo Extension. FFmpeg работает только с готовым MP4 и не разрезает текстовый prompt.

## 16. SOCKS5-прокси

SOCKS5-прокси включён по умолчанию через локальный Tor на `127.0.0.1:9050`:

```dotenv
USE_SOCKS5_PROXY=1
SOCKS5_PROXY=socks5://127.0.0.1:9050
```

При загрузке конфигурации до создания клиентов код устанавливает `HTTP_PROXY`, `HTTPS_PROXY` и `ALL_PROXY`. Google-клиент дополнительно получает:

```python
types.HttpOptions(client_args={"proxy": SOCKS5_PROXY})
```

Чтобы отключить прокси:

```dotenv
USE_SOCKS5_PROXY=0
```

Адрес `127.0.0.1` относится к серверу с ботом: Tor или Dante должны быть запущены на этом же сервере. Для поддержки SOCKS в httpx установлена зависимость `httpx[socks]`.
