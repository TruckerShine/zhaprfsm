# Telegram-бот для Veo 3.1

Telegram-бот на Python для генерации коротких видео через `veo-3.1-generate-preview`.

## Что умеет бот

После `/start` или `/menu` бот показывает inline-меню, а также добавляет постоянную кнопку **☰ Меню под полем ввода пользователя**. Это именно `ReplyKeyboardMarkup`, поэтому кнопка находится в нижней панели чата, а не прикрепляется к сообщению бота.

После нажатия `/start` бот отправляет два сообщения: первое включает нижнюю клавиатуру пользователя, второе содержит inline-меню. Telegram не позволяет прикрепить ReplyKeyboardMarkup и InlineKeyboardMarkup к одному сообщению.

Открывается пошаговое меню:

1. Выбор режима:
   - **🎬 Видео**;
   - **🖼 Фото**.
2. После выбора режима старое меню удаляется и появляется выбор ориентации:
   - **Горизонтально 16:9**;
   - **Вертикально 9:16**.
3. Для режима видео после ориентации появляются длительность и качество:
   - 4, 6, 8 или 15 секунд;
   - 720p, 1080p или 4K.
4. Для режима фото после ориентации бот сразу просит промпт или фотографию с подписью.

Поддерживаются:

- text-to-video;
- фотография с подписью как первый кадр видео;
- сохранение лица/людей с загруженной фотографии через инструкцию identity reference;
- до трёх референсных фотографий для видео и фото;
- фотография без подписи с последующим текстовым промптом;
- text-to-image через кнопку **🖼 Создать фото**;
- image-to-image: фото с лицом и подписью можно использовать для нового изображения;
- история результатов в SQLite (`history.db`);
- повторная отправка результата из истории;
- генерация видео со звуком;
- асинхронный polling операции Veo;
- ограничение параллельных генераций;
- `/cancel` и кнопка `⏹ Отмена` под полем ввода;
- понятное сообщение при квоте, `429`, `RESOURCE_EXHAUSTED` или rate limit.

## Режим 15 секунд

Veo 3.1 по API не создаёт один ролик длительностью 15 секунд напрямую. Поэтому кнопка **15 сек.** работает так:

1. создаётся первая часть длительностью 8 секунд, но пользователю она пока не отправляется;
2. бот автоматически вызывает официальное расширение Veo;
3. Veo добавляет ещё 7 секунд и получает логичное продолжение действия;
4. бот ждёт готовности второй операции и только после этого решает, что отправлять;
5. при наличии `ffmpeg` отправляются два отдельных файла: первая часть на 8 секунд и продолжение на 7 секунд;
6. без `ffmpeg` первая часть удаляется, а пользователю отправляется только полный файл примерно на 15 секунд.

Промпт продолжения автоматически содержит инструкции сохранить персонажей, окружение, стиль, движение камеры и звук, не начинать сцену заново и закончить действие логично.

Документация Veo описывает результат extension как единый объединённый файл «исходное видео + продолжение». Поэтому без `ffmpeg` бот специально не отправляет сначала первую часть: пользователь получает только один полный MP4 примерно на 15 секунд.

Чтобы получить именно два отдельных MP4-фрагмента, установите `ffmpeg`:

```bash
# Ubuntu/Debian
sudo apt-get update && sudo apt-get install -y ffmpeg

# macOS
brew install ffmpeg
```

Или укажите путь в `.env`:

```dotenv
FFMPEG_BIN=/usr/bin/ffmpeg
```

## Качество по документации Veo 3.1

Нативно модель поддерживает только три варианта:

- `720p` — обычное качество и единственный вариант для extension/режима 15 секунд;
- `1080p` — только при длительности 8 секунд;
- `4k` — только при длительности 8 секунд.

`320p` и `480p` Veo 3.1 напрямую через API не поддерживаются. В меню они отображаются как недоступные кнопки и при нажатии объясняют причину. Их можно добавить позже как отдельное пост-сжатие через ffmpeg.

## Важно: ключ из исходного сообщения нужно отозвать

В исходном сообщении был опубликован секретный Gemini API key. Считайте его скомпрометированным:

1. Откройте Google AI Studio и отзовите этот ключ.
2. Создайте новый ключ.
3. Запишите его только в локальный `.env` или в секреты сервера.
4. Не добавляйте `.env` в Git — он уже включён в `.gitignore`.

## Установка

Нужен Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate       # Linux/macOS
# .venv\\Scripts\\activate      # Windows PowerShell

pip install -r requirements.txt
cp .env.example .env            # Windows: copy .env.example .env
```

Заполните `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=токен_от_BotFather
GEMINI_API_KEY=новый_ключ_Gemini
```

Запуск:

```bash
python bot.py
```

## SOCKS5-прокси

SOCKS5-прокси включён по умолчанию, чтобы запросы с сервера в Амстердаме шли через локальный Tor/Dante:

```dotenv
USE_SOCKS5_PROXY=1
SOCKS5_PROXY=socks5://127.0.0.1:9050
```

Tor обычно слушает порт `9050`. Для Dante можно указать:

```dotenv
SOCKS5_PROXY=socks5://127.0.0.1:1080
```

Когда прокси включён, бот:

- устанавливает `HTTP_PROXY`;
- устанавливает `HTTPS_PROXY`;
- устанавливает `ALL_PROXY`;
- создаёт `google-genai` с `types.HttpOptions(client_args={"proxy": ...})`;
- отправляет запросы Google и Telegram через указанный SOCKS5-прокси.

`127.0.0.1` — это сам сервер, где запущен бот. На нём должен работать Tor или Dante. Если прокси не нужен, укажите:

```dotenv
USE_SOCKS5_PROXY=0
```

Не прописывайте рабочий прокси с логином/паролем прямо в `bot.py` и не публикуйте его в Git.

Зависимость `httpx[socks]` уже добавлена в `requirements.txt`; она нужна для поддержки SOCKS в httpx.

## Генерация и редактирование фото

В главном меню есть кнопка **🖼 Создать фото**. После нажатия можно отправить текстовый промпт, например:

```text
Кинематографичный портрет в неоновом городе, дождь, мягкий контровой свет, формат 9:16.
```

Чтобы использовать своё лицо, отправьте фотографию с подписью-промптом:

```text
Добавь моё лицо на этот кинематографичный портрет в неоновом городе.
```

Или отправьте фотографию без подписи, а следующим сообщением напишите промпт. В этом режиме используется модель `gemini-3.1-flash-image-preview`, которая получает фото и текст и возвращает PNG.

Для видео работает такой же принцип: выберите **🎬 Создать видео** или сначала формат/длительность/качество, затем отправьте фото с подписью. Фото используется как входное изображение Veo, а бот дополнительно добавляет инструкцию сохранять лицо, причёску и внешность в результате. Точная идентичность лица не гарантируется моделью в каждом кадре, поэтому лучше использовать чёткое фото лица и подробно описывать сцену.

Кнопка «Создать фото» использует текущий формат видео `9:16` или `16:9`. Размер изображения задаётся в `.env`:

```dotenv
GEMINI_IMAGE_MODEL=gemini-3.1-flash-image-preview
GEMINI_IMAGE_SIZE=1K
```

Допустимые размеры зависят от доступной модели изображения; обычно используются `1K`, `2K` и `4K`.

## Несколько референсных фотографий

В режиме видео или фото можно отправить до трёх фотографий без подписи. Бот сохранит их временно и после последней фотографии будет ждать текстовый промпт:

```text
Фото 1/3 сохранено. Отправьте ещё фото без подписи или напишите промпт.
```

После отправки промпта:

- в режиме фото все фотографии передаются Gemini Image вместе с текстом;
- в режиме видео при двух или трёх фотографиях создаются официальные `reference_images` Veo 3.1;
- если для нескольких reference-фото была выбрана длительность 4 или 6 секунд, бот автоматически переключает её на 8 секунд, как требует API для reference images.

Можно также отправить последнюю фотографию сразу с подписью. Тогда накопленные фотографии и последняя фотография будут использованы вместе, а генерация начнётся сразу.

## История генераций

После успешной отправки результата бот сохраняет его в SQLite-файл `history.db`:

- тип результата: фото или видео;
- исходный промпт;
- имя файла и MIME-тип;
- бинарные данные готового результата;
- дата и время.

Кнопка **📚 История** в главном меню или команда `/history` показывают последние результаты пользователя. Нажатие на пункт повторно отправляет сохранённое фото/видео.

Размер сохраняемого файла ограничивается `HISTORY_MAX_BYTES` (по умолчанию 50 МБ). Если видео больше лимита, отправка всё равно проходит, но такой файл в историю не попадает. Данные разных пользователей разделены по Telegram user ID.

База `history.db` добавлена в `.gitignore` и должна храниться на сервере рядом с ботом.

## Разделяется ли промпт при генерации видео?

Обычный промпт не разделяется: он отправляется в Veo одним запросом. В режиме 15 секунд происходит другое:

1. исходный промпт используется для первой части на 8 секунд;
2. бот автоматически создаёт второй prompt с инструкциями продолжить последний кадр логично;
3. этот prompt используется для Veo Extension на 7 секунд;
4. FFmpeg разделяет готовый медиафайл, а не текстовый prompt.

То есть бот не режет текст на куски. Он создаёт второй запрос только для продолжения видео.

## Кнопка под вводом пользователя

После `/start` в нижней панели Telegram появляется кнопка:

```text
☰ Меню
```

Она находится у пользователя под строкой ввода, а не под сообщением бота. Нажатие отправляет боту текст `☰ Меню`, после чего бот снова показывает главное inline-меню. Обработчик кнопки зарегистрирован раньше обработчика обычных промптов, поэтому слово `☰ Меню` не запускает генерацию.

## Команды

- `/start` или `/menu` — открыть главное меню и включить нижнюю кнопку.
- `/settings` — открыть выбор режима и параметров видео.
- `/history` — открыть историю сохранённых результатов.
- `/help` — подсказка по написанию промптов.
- `/cancel` или кнопка `⏹ Отмена` — остановить ожидание текущего результата в боте.

Во время генерации бот редактирует одно статусное сообщение примерно раз в 10 секунд. Он показывает приблизительный countdown: `2 мин 00 сек`, `1 мин 30 сек`, `59 сек` и так далее. Это именно оценка: Veo не возвращает точный процент и точное оставшееся время. Если прогноз закончился, бот пишет, что продолжает ждать, пока операция реально не завершится.

Обычный текст запускает видео в режиме по умолчанию. Для изображения нажмите **🖼 Создать фото**. Фото с подписью в режиме видео запускает image-to-video, а в режиме фото — image-to-image. Если в фото есть лицо, бот добавляет инструкцию сохранить внешность человека.

## Лимиты

Если Google вернёт ошибку квоты, `429`, `RESOURCE_EXHAUSTED`, `quota exceeded`, `rate limit` или `too many requests`, пользователь получит отдельное сообщение о лимите. Если Google включил в ошибку `retry in ... seconds` или `retry-after`, бот рассчитает обратный отсчёт до повторной попытки и покажет ориентировочное время сброса, например:

> ⚠️ Лимит на генерацию достигнут. Повторить можно примерно через 1 мин 02 сек (ориентировочно в 11:47).

Для дневных или проектных квот Google иногда не передаёт время сброса. В таком случае бот честно пишет, что точное время не получено, и не придумывает его.

Бот также ограничивает число одновременно выполняемых задач параметром `MAX_CONCURRENT_GENERATIONS`. Это локальная очередь процесса, а не квота Google. У одного пользователя одновременно может идти только одна задача: при попытке запустить фото во время генерации видео бот напишет «Сейчас идёт генерация видео, попробуйте запустить фото позже», и наоборот.

## Что исправлено по сравнению с исходным каркасом

Исходный пример использовал REST-методы `generateVideo`/`getVideo`, `operationId` и `videoUrl`. В проекте используется официальный Python SDK и актуальный объект `GenerateVideosSource`:

```python
source = types.GenerateVideosSource(prompt=prompt, image=image)
operation = client.models.generate_videos(
    model="veo-3.1-generate-preview",
    source=source,
    config=types.GenerateVideosConfig(...),
)

while not operation.done:
    await asyncio.sleep(10)
    operation = await asyncio.to_thread(client.operations.get, operation)
```

Результат берётся из `operation.response.generated_videos[0].video`, скачивается через `client.files.download(...)` и сохраняется локально перед отправкой в Telegram.

Дополнительно:

- секреты вынесены в `.env`;
- исправлена проверка `if __name__ == "__main__"`;
- синхронные вызовы Google SDK вынесены в `asyncio.to_thread()`;
- длительные операции не блокируют event loop;
- добавлены таймаут, отмена, очередь и безопасная обработка ошибок.
